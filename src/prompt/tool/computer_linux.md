## Linux

* Rust-only, no setup: clean Ubuntu 24.04 works, no groups/rules/apt packages.
* X11 = full: screen/window/multi stills + zoom/observe via X11 protocol, AT-SPI2 observe/act, XTEST raw input.
* Wayland = accessibility + one best-effort Screenshot-portal attempt; a system consent dialog may appear — never click it yourself; deny/timeout/missing → `degraded`, continue accessibility-only.
* Which one it is comes from the display server, never from an environment variable: an X connection that is XWayland (the session is Wayland, whether or not `WAYLAND_DISPLAY` is set) counts as Wayland, so its stills take the portal and its input is refused rather than written where the owner cannot see it.
* Raw input + cursor `degraded` on Wayland — prefer `ref` actions.
* `type`, `drag` and `scroll` with a point on a named window focus that window first and verify it: if it could not be focused, nothing is sent and the call fails with `degraded`. A coordinate `click` raises nothing here — the pointer lands under the point.
* A window `screenshot` is a crop of the full-screen capture, so its accessibility extents have to be reconciled with the captured pixels. On X11, whose accessibility coordinates are the screen's own pixels, an unreconcilable pair falls back to 1:1 and the crop is taken; on Wayland the still is refused with `degraded` instead of returning the wrong part of the screen — `screenshot { target: "screen" }` and `zoom` on it always work — and normalized coordinates are refused the same way. AT-SPI extents are taken to be screen-relative, as `CoordType.Screen` asks; a toolkit that reports window-relative extents cannot be detected.
* Window stills show visible pixels (occluders visible). A minimized window is refused with `degraded` for a still, for coordinate mapping and for `observe` — its frame is the one it had before it was minimized; restore it first.
* No streaming in v1.
* Offered only when a GUI session with a reachable session D-Bus exists. The accessibility connection belongs to this process and is rebuilt when the service behind it closes it, so an at-spi stack that starts later, or restarts, is picked up by the next call.
* `permission-denied` means a D-Bus call was not authorized.
* A locked session is `desktop-unavailable`: the state is systemd-logind's lock hint for the session — the one lock signal the system publishes for every desktop, never a guess — and a session that does not answer it is not refused.
* Typing goes one character at a time and a gesture is a sequence of XTEST events, so an interruption after part of one comes back `applied but unconfirmed`, saying how many characters or wheel ticks were sent and what may still be held or half-delivered — the same answer an element action gives when the application's accessibility call times out at the bus, because it may have acted on the request anyway. A failure before any of it landed — a pointer that never moved, a modifier that never went down — is a plain failure, and can be repeated. Any result that names a modifier it could not release leaves it down — a call lets go of what it can still reach on the way out, an error return or a panic included, but one abandoned inside a request of the server releases nothing until that request returns — so every later chord and typed character may be modified: ask the owner to clear it before you act again.
* mahbot's own window publishes no AT-SPI surface, so it is not in `apps`/`windows`, cannot be observed or acted on by `ref`, and has no window still. `target: "screen"` input, key chords and `type` still reach it.
* A tree keeps at most 120 characters of a node's value — the reader stops one character past what the dump shows — and 200 of a node's name, and a window or application title is kept to the same 200. A longer one keeps its beginning, marked with an ellipsis, and the header states the cut (a cut title counts as a cut name). One node contributes at most 1000 children: a target that advertises more (a spreadsheet's cell list is the classic case) has its children not read at all, and the header says so — narrow the target instead of assuming they are absent.
* A still is bounded by the product, not by the compositor: one call may hold at most 134 megapixels (512 MiB of RGBA) at once — the virtual-desktop composite, the display tile being blitted, a window's crop and the RGBA the portal image was converted to all count. A call that would need more is refused with `degraded` naming the ceiling, never returned clipped, so `zoom` cannot deliver there either — and a window still is a crop of the same screen capture, so naming a window does not lower the cost. On Wayland the portal's file is read only up to 128 MiB, and the decode is bounded by the shared raster envelope and by what is left of the call's allowance (16384 px a side at most), so a portal still this call cannot hold is refused before it is converted; the refusal names the decode cap that was applied.
* No accessibility exchange can hold the call: every D-Bus request carries mahbot's own 10-second method timeout, so an accessibility service that does not answer costs one attribute or one child — exactly as if it had refused it — and the read continues. Each call's accessibility work is bounded as a whole: 120 seconds for an observation, 130 for an element action's (it observes first), 20 for a listing or a surface lookup — resolution included, since finding a window walks every application. In a listing or a focused-window search each application gets a 10-second share of that budget, checked before every request it makes, so it can overrun by at most the one request in flight: a hung application is caught and skipped, named as unread in a listing or as the reason a search found nothing, while the windows read around it are kept — a skipped application is a partial answer, not a failed call. A budget that runs out ends the call with `degraded`, naming the surface; retry then, or take a screenshot instead. A responsive target is unaffected — a 4000-node tree stays well inside the observation budget.
