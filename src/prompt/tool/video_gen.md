Generate a clip with an AI video model, or restyle a clip you already have. One call, three mutually exclusive shapes, decided by the inputs you pass:

1. **A new clip** — `prompt` alone, optionally with ONE reference picture in `images` to start from (image-to-video; a local `uploads/`/`generated/` path, never a URL); omit the picture for text-to-video. Takes `duration`, `resolution`, `aspect_ratio`, `size`, `generate_audio` and `seed`.
2. **A new clip anchored on frames** — `first_frame` and/or `last_frame` (a local `uploads/`/`generated/` path or a public HTTPS URL; JPG/JPEG/PNG/WEBP/HEIC/HEIF, at most 30 MB) to pin the exact first and last frame.
3. **An edit of an existing clip** — `video_url` (a public HTTPS URL, or a local path from the workspace `uploads/` received-attachments dir — shown as "[Saved video: /path]" in the chat — or from the workspace `generated/` dir — shown as "[VIDEO:path]", the output of a previous call) plus the `prompt` describing the edit. Up to 9 reference images via `images` — local `uploads/`/`generated/` paths or public HTTPS URLs — guide style/subject/identity.

`prompt` is one text input for all three shapes, capped at 5000 characters. Frame anchors are mutually exclusive with ALL reference inputs: a request combining them with `video_url` or `images` is rejected. A parameter belongs to the shape that takes it: `resolution`, `aspect_ratio`, `size`, `generate_audio` and `seed` describe a new clip only, and passing one together with a video reference or with frame anchors is refused rather than silently dropped. An input that is present but empty (`video_url`, an anchor, a picture in `images`) names nothing and is refused too — omit the argument instead.

For a style change, pair the source with a style-reference image (generate one via `image_gen` if none exists) and give each reference an explicit role in the prompt; name the target style concretely; keep composition, camera, movement and timing unchanged and change ONE visual category per call, in order: background → wardrobe → lighting → grade. Full restyle while preserving the plot is at the edge of every model: iterate single-category passes and verify each pass before continuing.

This tool changes what a model renders; it does not assemble a recording. Cutting, trimming, retiming, titles over real footage and sound on its own track belong to `hyperframes` (when it is in your tool set): take the footage there instead of asking a model to re-render it.

A new clip's reference must be PNG, JPEG or WebP. References over 1.5 MB are compressed (downscaled and re-encoded as JPEG), and one near the cap may be compressed further to keep the request within the ~2 MB body budget. Missing, unreadable or undecodable references are hard errors — the tool fails visibly rather than falling back to text-to-video, so fix or remove the reference and retry.

Local paths are accepted ONLY from `uploads/` or `generated/`; any other is rejected. An edit's guiding pictures and the frame anchors must be JPG/JPEG/PNG/WEBP/HEIC/HEIF and at most 30 MB; source clips are limited to 50 MB, and local MP4/MOV clips whose duration falls outside the active model's verified input range are rejected before upload. Per-model parameter support is listed in the active model's capability block when present; otherwise keep parameters conservative and model-agnostic.

Each invocation bills a paid job and can take up to 1 hour (provider queue stalls are common — do not abandon a pending job). Never repeat a call that was already submitted — a stalled generation and a timed-out edit alike — because that bills a second run; report the timeout instead. Returns the path to the video, followed by the clip's timeline — its frames grouped four to a picture, each frame with its mark and each picture naming the frames it holds, the speech with marks and text, and a sound label where there is no speech — use [VIDEO:path] in your reply to send it. Never make more than one call before sending the result to the user — avoid long waiting and excessive billing.
