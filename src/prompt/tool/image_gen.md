Generate an image using an AI image generation model. Supports text-to-image and image-to-image (when reference images are provided). The generated image is automatically attached to your conversation context as a native image, so you can see what you generated without emitting an [IMAGE:path] marker. The tool's output still carries the marker so the image is delivered to the user.

The image model the account picked is tried first; when it cannot produce the picture or cannot be sent the request at all — it is gone from the provider's catalog, cannot make pictures, cannot take as many reference images as the request carries, or cannot express the requested size — the other image models the account's picker offers are tried in turn, and the request is a success once one of them serves it. When a fallback served the request, the result names the model that produced the picture and what happened with the account's own model: what it answered, or that it was never sent to and why. When another model produced the picture, you MUST tell the user which model made it and what happened with their own model when you send the picture.

Reference image limits: each reference must be a PNG, JPEG, or WebP file. References larger than 1.5 MB are automatically compressed (downscaled and re-encoded as JPEG) to fit, and multiple references may be compressed further so the total request stays within the ~2 MB request body budget. Local paths are accepted ONLY from the workspace `uploads/` directory (received media attachments) or the workspace `generated/` directory (previously generated media); any other local path is rejected. Missing, unreadable, or undecodable references, more references than the provider accepts (16), or reference material over the total input-size cap are hard errors — fix or remove them and retry.
