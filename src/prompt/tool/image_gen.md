Generate images using an AI image generation model: text-to-image, or image-to-image with reference images. One call carries ONE `prompt`, shared by up to 10 `generations` — a single picture is a list of one. Each generation carries its own reference `images`, its own `aspect_ratio` and its own `size`, so one instruction can retouch a whole set of photographs or produce a set of different shapes. A setting left unset on a generation behaves exactly as a single picture with it unset; it never borrows a sibling's value. A generation's position in the list, counted from 1, is how the result names it. The generations are requested together, so a batch takes about as long as its slowest picture.

Every produced picture is attached to your conversation as a native image, so you see them without emitting [IMAGE:path] markers; the result still carries one marker per picture so the pictures reach the user. The result reports one line per generation, in position order: a produced picture's marker and — when a fallback model served it — the note about that model, or one line saying why that generation produced nothing. Once the call is under way a generation failing never costs the others; only a call that produced nothing at all fails as a whole, and then its message names every position. Tell the user what the result says for each picture, and for a generation that produced nothing, which position it was and why.

The account's chosen model is tried first; when it cannot produce the picture or take the request at all — gone from the catalog, cannot make pictures, cannot take that many references, or cannot express the requested size — the account's other models are tried in turn, and the request succeeds once one serves it. When a fallback served it, the result names the model that produced the picture and what happened with the account's own model (what it answered, or that it was never sent and why); you MUST tell the user both when you send the picture.

Each reference must be PNG, JPEG or WebP. References over 1.5 MB are compressed (downscaled and re-encoded as JPEG), and several may be compressed further to keep the request within the ~2 MB body budget. Local paths are accepted ONLY from the workspace `uploads/` (received attachments) or `generated/` (previously generated media); any other is rejected. Missing, unreadable or undecodable references, more than the provider's 16, or reference material over the total input cap are hard errors — fix or remove them and retry.
