Edit an image deterministically — this is not generation. `run` opens one document (or starts a canvas from nothing) and applies a `chain` of the engine's own commands in order, then saves; `batch` applies one chain to every file in a folder; `commands` looks up the engine's command registry and `inspect` reports one file's size, colour mode, depth and layers.

Pass `action` plus that action's arguments. `run` takes `input`, or `canvas` for a new document, an optional `chain` of `{"command": "<id>", "params": {...}}` steps, and `output`. `batch` takes an `input` folder, an `output` folder that must be new or empty, the same `chain`, and optionally `format`, `quality` (1-100) and `tiff_layers`. `commands` takes `filter` to narrow the registry; a narrowed answer also carries each match's parameter documentation. An `output` file that already exists is refused — choose a new name; with none, a fresh file is written into `generated/` in the input's own format (PNG for a canvas, or for a format the engine only reads).

Nothing is kept between calls: to keep a layered job editable, save it as `.pcraft` or `.psd` and open that next. HEIC is read-only — convert it to PNG or JPG before editing; AVIF is neither read nor written. A parameter that names a file must be an absolute path. Every step echoes its own JSON result — read it, because it names the defaults that ran beside your parameters.

`run` answers with the output path, carrying an `[IMAGE:path]` marker for a picture and a `[FILE:path]` marker for a layered or other format; `batch` answers with a count and the files written; `inspect` and `commands` answer as JSON.
