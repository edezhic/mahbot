Turn a file into an ordinary picture. The file is rendered and saved as a PNG in the workspace, and the picture is automatically attached to your conversation context as a native image — so you see it in the same step, and you do not need to read the file separately. The tool's output still carries an [IMAGE:path] marker, which is what sends the picture to the user, exactly like a generated image.

SVG is one input: one you wrote, one a user brought, or one authored elsewhere. What the drawing asks for is honoured — its own transparency, the images it refers to (looked up beside it, and only where you may read files yourself, so nothing outside your own reach is ever read), and its text, drawn with the fonts this machine has where the file names a family, and with the product's own font where the file names none or names a family the machine cannot supply. A script neither can draw may be missing: that approximation is accepted. The picture therefore looks slightly different on different machines.

A PDF is the other: name the page to render with `page` (1-based). A single-page PDF needs none; a PDF of several pages requires it, and the refusal says how many pages the document has. A page past the end, and a page named for a file with no pages, are refused the same way. The picture shows the page's visible area, so a crop is honoured, and it is an ordinary PNG of the same kind and long-side cap as any other. Interactive elements — form values, comments, links — are not part of a picture; leaving them out is accepted, not a defect.

The picture keeps the source's aspect ratio, its long side capped at a fixed size and never enlarged, so a small drawing or page stays small.

Refused, with a message naming the reason: a file that cannot be read, one larger than the read limit the read tool applies, an empty file, anything that is not SVG markup or a PDF — a gzip-compressed drawing that cannot be unwrapped included — and a PDF that is password-protected or otherwise cannot be opened.
