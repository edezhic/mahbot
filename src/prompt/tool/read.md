Read file contents with line numbers. Preferred over shell `cat` for reading files — it provides line numbers for reference, supports offset/limit for partial reads, and can list code structure via AST symbols.

{{path_policy}}

When the path is a directory, the tool lists its contents instead of returning an error. The directory listing groups subdirectories and files with sizes and an extension summary. Note that `mode`, `offset`, and `limit` parameters only apply to file reads — they are silently ignored when a directory is passed.

Modes:
- `content` (default): Outputs a file or a range (using `offset`+`limit`) with line numbers. Large outputs are truncated to a small budget (~5 KB) — for big files, read in slices with `offset`/`limit`, or navigate via `symbols`/`zoom`. Handles any file type; binary files are read with lossy UTF-8 conversion, except the document containers converted below and a background shell session's own output file (read as a program's output). When the path is a directory, lists the directory contents.
- `symbols`: Lists all AST-level symbols (functions, structs, impl blocks, etc.) with line ranges — the quickest way to map a large file's structure without reading it whole. Works for supported code formats only (Rust, JS/TS, Python, Go, C, Ruby, SQL, Markdown, JSON, TOML, CSS, HTML, shell), not arbitrary formats.
- `zoom`: Extract a single symbol's full source by name (requires `symbol` parameter). Same supported-formats limit as `symbols`. Use with the output of `symbols` mode to drill into specific definitions.

When a content-mode path is a raster image (PNG, JPEG, or WebP), the tool reads and attaches it to the conversation as a native image the model can inspect, instead of returning lossy text. Other binary formats that cannot be decoded (e.g. GIF, BMP, HEIC) are reported as unsupported. Reading the same image twice returns a reference to the already-attached image rather than adding it again.

A content-mode document container — a PDF, a Word `.doc`/`.docx`/`.docm` document, an Excel `.xls`/`.xlsx`/`.xlsm` table, or a PowerPoint `.ppt`/`.pptx`/`.pptm` presentation — is converted, not returned as bytes: an encrypted file is answered as `password-protected`, and an old binary file is read as that, whatever its name. Its text is returned, or its path when too long. A chart in a Word, Excel or PowerPoint package is described where it sits (a layout's or master's chart stays counted): its kind under `{{chart_header}}` — `{{chart_none}}` when it names none — its `{{chart_title}}`, any `{{chart_text}}` or `{{chart_label}}`, and one `{{chart_series}}` line per series — numbered `{{chart_series_numbered}}` when the part names none — of category: value, a bubble's `{{chart_size}}` beside its value, shown as a sheet shows them, any excess counted; one without readable values says so in place (`{{chart_no_values}}`, `{{chart_attached}}`, `{{chart_unreadable}}` or `{{chart_extended}}`) and stays in the report. Every reading says what it did not show, one line per kind ({{unshown_report}}); an image it meant to deliver keeps the note saying why it is not there rather than a line of the report, and what a reading never looks at is not in the report either; formatting, themes and service parts stay out of the text. Pages and images with no text are attached as images (at most 5; more by path), and a page whose text was read is not drawn, its drawings out of reach. A document with neither text nor images, or one that will not convert, gets a plain note.

An old binary `.doc`/`.xls`/`.ppt` is read only — this tool never edits one — and comes back in the shape its family's reading below gives, as far as its reader reaches. Hidden sheets and slides, merged ranges, cell comments, hyperlinks, defined names and a formula's text are never read or shown; a presentation gets no title, hidden-slide or diagram mark, and a document's stories come as one labelled block each — `{{doc_headers_footers}}:`, `{{doc_footnotes}}:`, `{{doc_endnotes}}:`, `{{doc_comments}}:` — with no comment author.

A `.xlsx`/`.xlsm` workbook comes back as `Sheet "<name>":` blocks in workbook order, one line per valued cell, `A1: 42`. A formula with no stored value is shown as its formula, one with both as `42 (=SUM(B1:B2))`; a sheet holding nothing says so, one holding a chart says `{{chart_sheet_mark}}`. Every value is the one Excel displays in its format — a date as a date, a percent as a percent — so write back the number stored, not its displayed text; a format it cannot reproduce shows the stored number, marked `{{mark_stored}}`. Hidden rows, columns and sheets are marked as hidden, a merged range where it is; a cell's comments follow the sheet's cells, a hyperlink is marked on its cell, and defined names follow the last sheet as a `Defined names:` block. A pivot table's values and a shape's or text box's text are never read.

A `.docx`/`.docm` is read beyond its body: a table is a `Table N:` block, one line per row under its `R1:` prefix, one `C2:` token per cell, a merged cell marked `(spans C1-C2)` and `(part of R1C1)` on each continuation. The headers and footers follow, one block per part, then footnotes, endnotes and comments, each indented under its heading, a definition nothing refers to saying so, and `[footnote 1]`, `[comment 1]` or `[comment 1 starts]`…`[comment 1 ends]` marking where it belongs. A field's page number or date is reported as that field (`[field PAGE]`), and a text box's text is shown once as an indented `{{text_box_mark}}` block.

A `.pptx`/`.pptm` yields each slide's text under a {{ppt_slide_label}} block and its notes under {{ppt_notes_label}}: a declared title is marked `{{ppt_title_mark}}`, a hidden slide `{{ppt_hidden_slide_mark}}`, diagram text follows under `{{ppt_diagram_text_mark}}` (`{{ppt_diagram_text_lost_mark}}` when unreadable, `{{ppt_no_text_mark}}` for a slide with none). A slide's layout and its theme are not read.

For a PDF the text comes page by page: a `Page <n>:` block per page that produced any text, and a page with none is delivered as an image instead. When the document carries marks, an `Annotations:` section follows, one entry per mark as `<kind>[ (<author>)] on page <n>`, its text under it; the kinds are `note`, `free text`, `highlight`, `underline`, `squiggly underline`, `strikeout`, `ink`, `square`, `circle`, `polygon`, `polyline`, `line`, `caret`, `stamp` and `signature`. When the form holds values, a `Form fields:` section follows, one line per field as `<field name> [on page <n>]: <value>` — a checkbox or radio group `checked` or `not checked` plus the option it holds, a choice field its selected option, and a form whose values could not be read saying so rather than looking empty. Pages with no usable text layer and pages that could not be read are attached as images.

Unaccepted tracked changes are never passed off as final text: `[ins]…[/ins]` was inserted, `[del]…[/del]` deleted, `[moved-here]…[/moved-here]` and `[moved-away]…[/moved-away]` moved, and `[ins ¶]`, `[del ¶]`, `[moved-here ¶]`, `[moved-away ¶]` revise a paragraph mark; a row or cell added or removed says `(inserted)` or `(deleted)`, and `[fmt]`, `[fmt ¶]`, `[fmt section]`, `(merge revised)`, `(formatting revised)` revise formatting alone. The document opens with an `Unaccepted tracked changes: …` line counting them and naming their authors.

Reading a credential-bearing file — `.env*`, a `.pem`/`.cer`/`.crt` certificate, `.key`/`.p12`/`.pfx`, or a known credential config (`.netrc`, `.npmrc`, `.pypirc`, `.git-credentials`, Maven `settings.xml`/`settings-security.xml`, Gradle `gradle.properties`/`init.gradle*`, cargo `credentials.toml`) — returns its content with the credential values masked. Every other file comes back as it is, and a secret stored under a name the masking does not recognise is returned whole.

Files larger than 10 MB are rejected, except document containers, which are accepted up to 50 MB.
