Create and edit documents: write a new .docx/.xlsx/.pptx/.pdf, fill a user's own sample, edit an existing Office file, and edit PDF pages. Every action is data — a fixed operation over the values you pass — and every path you pass is {{input_location}}.

**Every action.** The file you pass is never modified: each call writes a new file into the workspace's `generated/` directory, whose name the tool owns — `file_name` is only a base name. Name each file you produced in your answer with its `[FILE:…]` marker: a file no answer mentions may be swept away before delivery. An input may be up to {{input_mb}} MB, and an embedded image must really be a PNG or a JPEG, not merely named like one.

**Editing** (`docx_edit`/`xlsx_edit`/`pptx_edit`): an edit is applied whole or not at all, and every part it does not name — images, fields, headers and footers, comments, macros, anything else — is carried into the copy as it was. The package is re-compressed rather than rebuilt byte for byte, and aggregate formatting (styles, themes, a presentation's layouts and animations) and complex objects (charts, pivot tables) are not rebuilt: what they hold or how they look may stay as the file had it. The answer names every loss the call found, and a signature the file carried is invalidated.

**Documents.** A text op addresses a fragment of the document's own body text, matched inside one paragraph and never across paragraphs — every occurrence in every matching paragraph is rewritten, while `remove_paragraph` removes every paragraph holding it. A text box's own text and a table cell's are addressed; a header's, a footer's, a footnote's, an endnote's, a comment's and a field's cached result are not, and a fragment only they hold is refused as that part's text. What a reading PRINTS around the text it shows is the reader's, not the file's: the marks it prints in brackets ({{docx_inline_marks}}) and the labels it adds ({{docx_label_marks}}), plus the indentation it prints under a block, are not text an edit addresses, so a fragment that is only one of those is refused for what it is. A tab and a line break a reading shows are markup in the file (`<w:tab/>`, `<w:br/>`): a fragment holding one is refused, and a rewrite (`replace_text`, `insert_text`, `remove_text`) may not match across one — name a fragment on either side. A fragment found nowhere is refused with the reason it was not found. A fragment or a replacement is at most {{edit_text_max}} characters. Making a fragment bold, italic, underlined, struck through, sized or coloured formats the whole of the run it sits in, and the answer says so.

**Sheets.** `set_cell` writes a value and leaves the cell's own formatting alone. `format_cells` is what gives a table its look — the one op that changes how cells appear without touching what they hold — and a cell keeps the look its row and column give it. `clear_cell` empties a cell and keeps its formatting.

**Presentations.** A slide is its 1-based number as the reader shows it, and a text op names a fragment of text that must be on it — whitespace alone matches nothing. The labels and marks a reading prints — {{ppt_slide_label}}, {{ppt_notes_label}}, {{ppt_title_mark}}, {{ppt_hidden_slide_mark}}, {{ppt_diagram_text_mark}}, {{ppt_diagram_text_lost_mark}} and {{ppt_no_text_mark}} — are that printing, not text on the slide, nor is the text a diagram holds, which no edit changes, nor the text a slide's own speaker notes hold: `replace_notes`, `remove_notes` and `add_notes` are what address those.

**Filling.** `fill_template` and `pdf_form_fill` substitute `values` keyed by name. A Word or PowerPoint sample is filled at its `{name}` placeholders; a spreadsheet is filled cell by cell, where a cell holding exactly one placeholder takes a number as a number. Anywhere else a substitute is written as text and never becomes a formula. A placeholder you give no value is left as it was and reported back to you. A PDF's form fields are separate from its page content.

**PDF pages.** `pdf_text` and `pdf_image` change the pages they name: what they draw becomes page content rather than an annotation object, and text already in the file is never reflowed to make room for it. `pdf_rotate` adds a rotation to the pages it names and draws nothing. A PDF's existing text is not addressable — there is no PDF find-and-replace.

**PDF files.** `pdf_merge` and `pdf_split` build a fresh document and carry the pages into it, so only the pages come along: a document's own description, its bookmarks and named destinations, its tags, its page labels, its embedded files and its form fields — a merged form is no longer fillable — are not carried, while page content, page rotation and annotations are, and a carried link or annotation may name a page the new file does not have; a `metadata` object may describe the new file.

**PDF description.** Every PDF-writing action takes `metadata`, the file's own description — {{pdf_metadata_fields}}. A field named is set, a field you do not name is left as the file has it, and an empty string clears one; `keywords` is one text. A date is {{pdf_date_format}}. Editing a PDF never rewrites the description it already carries; an existing `modified` date advances to the write unless you name it, and no entry is invented for a file that carries none. A file the tool builds names `mahbot` as its producer.

**Refusals.** A file whose content is encrypted is `password-protected` whatever its name; a file that is really an old binary `.doc`/`.xls`/`.ppt` is read but never written — convert it to one of the OOXML families, or to a PDF for a PDF action; an action given a file of another family, or a container that is neither a document nor a recognised format, is refused as what the file really is — decided from its content, and from its name only where the content names no format at all.
