# report_gap — reference

## Arguments

- `report` — one piece of prose: what the user needed and what was missing, described together in general terms. The length bounds are the numbers the standing description states, counted in characters after trimming.

Write what would have been needed to serve the request, not a transcript of the conversation, and not the user's personal data beyond what the gap itself requires.

## One-way

The report goes to the owner's assistant, which sees the text and the name of this account. Nothing comes back through it: the owner's assistant answers its own user, and apart from this call's own result nothing about the report appears in this conversation. A report grants nothing — what an account may use stays the owner's decision.

## Limits

The daily cap is the one the standing description states, per account. A report identical to one this account already filed today is refused **without** spending the day, so a repeat costs nothing and a new report can still be filed. The cap is a ceiling, not a target.

## Result

Every refusal is an ordinary answer with the reason, never an error: too short, too long, the day's cap reached, an identical report already filed, or the report could not be written down. Only a durable hand-over earns `The report was passed on to the owner's assistant…`, and that answer says plainly that no tool came with it.
